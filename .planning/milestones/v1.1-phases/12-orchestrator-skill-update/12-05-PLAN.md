## Repo-root probe output format (scripts/probe_dynamic_tools.sh)

The probe emits lines via three helpers (verified by reading scripts/probe_dynamic_tools.sh):
- `[OK]   ...`
- `[WARN] ...`
- `[INFO] ...`

Relevant tokens the populate path keys off:
- `ptrace_scope=<N>` (e.g., `[OK]   ptrace_scope=0 (parent-child tracing permitted)`)
- `[OK]` lines for `binfmt_misc` (when mounted)
- `[OK]` lines for `unshare --net round-trip: passes` (netns_feasible)
- **qemu arches:** the probe emits ONLY a COUNT SUMMARY of the form
  `[OK]   qemu-*-static binaries available: N arches`
  AND a literal `<arch>` token (via the `for arch in arm aarch64 mips mipsel ppc ppc64 i386 x86_64 riscv64 sparc;` loop, but only the count is printed, NOT the per-arch names).
- Exit code: 0 if all checks pass, 1 if any [WARN] fired.

This is why the existing `qemu-\K[a-z0-9_]+(?=-static)` regex in init_status_tree.sh never matches: there are no `qemu-<arch>-static` substrings in the probe output. The fix: in init_status_tree.sh, do NOT parse qemu arches from probe output — directly probe `command -v qemu-<arch>-static` for the same arch list the probe uses.

## MCP Streamable HTTP (2025-03-26) requirement

Per the MCP spec, POST requests to a Streamable HTTP server MUST include the header:
```
Accept: application/json, text/event-stream
```
The server may respond with either:
- `Content-Type: application/json` (plain JSON-RPC envelope) — parse directly with jq
- `Content-Type: text/event-stream` (SSE-framed; one or more `data: <json>` lines) — strip
  the `data: ` prefix from the relevant line, then parse with jq.

FastMCP (used by mcp-gateway) defaults to SSE-framing the response when the Accept
header includes `text/event-stream`. The fix needs both:
1. Add the Accept header to curl
2. Add SSE-prefix-strip before jq parse (in case the server frames as SSE)

```bash
        # MCP Streamable HTTP (2025-03-26): server may respond with `text/event-stream`
        # (SSE-framed) instead of plain JSON. Strip a leading `data: ` from any line
        # so the downstream jq parse sees a clean JSON-RPC envelope.
        # If the response is already plain JSON, this leaves it unchanged.
        resp=$(printf '%s\n' "$resp" | sed -n 's/^data: //p; t; p' | tr -d '\r')
        # If sed produced nothing (no data: lines, no other lines), the resp will be empty;
        # restore the original in that fringe case to avoid masking a real JSON-RPC reply.
        if [[ -z "$resp" ]]; then
          resp=$(curl -sf --max-time 5 -X POST \
                   -H "Authorization: Bearer $token" \
                   -H "Content-Type: application/json" \
                   -H "Accept: application/json, text/event-stream" \
                   -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"get_dynamic_capabilities","arguments":{}}}' \
                   "http://${host}:${port}/mcp" 2>/dev/null || echo '')
        fi
```

Simpler alternative if the above feels brittle — replace with this single robust pipeline that handles both shapes in one pass (preferred form):
```bash
        # MCP Streamable HTTP (2025-03-26): server may respond with text/event-stream
        # (SSE-framed `data: <json>` lines) or plain JSON. Normalize to plain JSON.
        # awk: if any line starts with 'data: ', emit only those (stripped); else emit all.
        resp=$(printf '%s' "$resp" | awk '
          /^data: / { sub(/^data: /, ""); sse=1; print; next }
          { if (!sse) print }

```
