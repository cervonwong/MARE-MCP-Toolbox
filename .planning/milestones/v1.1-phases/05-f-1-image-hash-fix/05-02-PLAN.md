<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| run_docker.sh → scripts/compute_image_hash.sh | A new subprocess boundary. Env vars are forwarded explicitly (INSTALL_BINARY_NINJA, BINARY_NINJA_ZIP, INSTALL_IDA_PRO, IDA_PRO_ZIP) via env-var prefix syntax, not via global `export`. The helper inherits PATH from the calling shell. |
| developer-supplied env / CLI args → BINARY_NINJA_ZIP / IDA_PRO_ZIP paths | The helper passes these paths to `sha256sum`. `sha256sum` reads but never executes the contents — no command-injection surface. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-02-01 | Tampering | scripts/compute_image_hash.sh | mitigate | `set -euo pipefail` (Task 1 §3) blocks silent failure; all variable expansions inside the helper are double-quoted (`"$BUILD_ROOT"`, `"$BINARY_NINJA_ZIP"`); no `eval`, no unquoted command construction. |
| T-05-02-02 | Tampering | BUILD_ROOT positional arg | mitigate | The helper rejects non-directory build roots (`[[ ! -d "$BUILD_ROOT" ]]` → exit 2) and absent Dockerfiles before doing any work. Attacker cannot redirect the hash to a different tree without an explicit caller-provided path. |
| T-05-02-03 | Tampering | BINARY_NINJA_ZIP / IDA_PRO_ZIP paths | accept | The helper only calls `sha256sum` on these paths — `sha256sum` is read-only and has no shell-injection surface. Existing licensing constraint (CLAUDE.md) already requires user-supplied zips; the helper does not relax that posture. |
| T-05-02-04 | Information Disclosure | hash output | accept | INFO — the hash is the docker image tag; it is non-secret by design. |
| T-05-02-05 | Denial of Service | helper invocation | accept | LOW — the helper has a bounded workload (one `find` over `mcp-gateway/` + `docker-bin/`). No network, no fork-bomb surface. |
| T-05-02-06 | Elevation of Privilege | new scripts/ directory | accept | INFO — `scripts/compute_image_hash.sh` has mode 0755, lives at repo root, and is invoked by an already-privileged caller (the developer). No setuid, no new capabilities. |

All threats are LOW/INFO/MEDIUM mitigated. No HIGH severity threats. No block-on-severity gates triggered.
</threat_model>
