# Milestone v1.0: Remote MCP Foundation

**Status:** ✅ SHIPPED 2026-04-27
**Phases:** 1-4
**Total Plans:** 16

## Overview

This milestone delivered two major capabilities to MARE-MCP-Toolbox: IDA Pro as a third disassembler backend (alongside Binary Ninja and Ghidra), and a remote MCP gateway that exposes the container's analysis tools over Streamable HTTP for external clients (Claude Code, mastra.ai). Work progressed from backend integration (IDA Pro working locally inside the container) through gateway construction (curated tool surface with auth) to container wiring (dual-mode entrypoint, compose config) and finally external client integration (config templates, end-to-end workflows).

## Milestone Summary

**Key Decisions:**

- Add IDA Pro as third disassembler option (rationale: user request, IDA is industry standard for RE) — ✓ Phase 1
- Use ida-pro-mcp (mrexodia) over jtsylve fork (rationale: built-in SSE transport, fits remote MCP architecture) — ✓ Phase 1
- IDA > BN > Ghidra fallback chain (rationale: pick best available; codified in `configure-agent-mcp.sh` and gateway backend detection) — ✓ Phase 1, restated Phase 2 Plan 05
- Custom FastMCP gateway over `mcp-proxy` (rationale: gateway-native curated tools + transparent backend pass-through + `/upload` + uniform bearer+Origin auth in one process; `mcp-proxy` is 1:1 stdio→HTTP bridge only) — ✓ Phase 2 D-01..D-20
- Backend disassembler tools pass through under their NATIVE names; clients call `get_active_backend()` to discover the active surface (rationale: avoid lossy normalization across IDA/BN/Ghidra) — ✓ Phase 2 D-07
- Bearer token + Origin header auth (no OAuth 2.1) (rationale: single-team local/VPN deployment) — ✓ Phase 2 D-04
- sha256 content-addressed upload layout `<UPLOAD_DIR>/<sha256>/<filename>` with 1 GB cap (rationale: dedup by content; round-trip via `resolve_sample`) — ✓ Phase 2
- `PinnedBackend` async ClientSession lifespan-managed (IDA Streamable HTTP, BN/Ghidra stdio subprocess) with `asyncio.Lock` serialization (rationale: long-lived session avoids reconnect cost; fail-loud) — ✓ Phase 2
- Dual-mode architecture: one image, `./run_docker.sh` (local) vs `./run_docker.sh --remote` (gateway) (rationale: preserve v1 workflow while adding new capability) — ✓ Phase 3
- `MCP_GATEWAY_ENABLED` Dockerfile guard for byte-identical local mode (rationale: structural guarantee that local mode has zero gateway daemon leak) — ✓ Phase 3
- Single launcher with `--remote` flag vs separate compose files (rationale: one UX entry point; mode selected by flag → env exports → compose overlay) — ✓ Phase 3
- Two-mode README framing (rationale: surface dual-mode product story to first-time readers) — ✓ Phase 4 D-16
- mastra `@mastra/mcp ~1.3.1` pin (rationale: tested combination per Tech Stack table) — ✓ Phase 4 D-08

**Issues Resolved:**

- IDA detection was originally written for stdio `ida-mcp`; corrected to use `idalib-mcp` and SSE transport (Phase 1 Plan 03 — gap closure)
- GW-03 wording was inverted (BN > IDA > Ghidra); corrected to IDA > BN > Ghidra across REQUIREMENTS.md and CONTEXT.md (Phase 2 Plan 05)
- `get_active_backend` MCP tool initially not registered; wired in during Phase 2 Plan 05
- Mastra starter initially used `sample_id` from `/upload` response instead of `sha256`; corrected during Phase 4 Plan 04
- Mode selection via env exports collided with seedfile guard; resolved by Dockerfile `MCP_GATEWAY_ENABLED` guard at process boundary (Phase 3)

**Issues Deferred (to v1.1):**

- **F-1: `run_docker.sh` content-hash misses `mcp-gateway/`** — surfaced during 2026-05-11 UAT. Edits to gateway code pass unit/e2e tests but never reach the running container until the image cache is manually invalidated. Fix: extend `DOCKERFILE_SHA` in `run_docker.sh:209-222` to checksum `mcp-gateway/` as well.

**Technical Debt Incurred:**

- E2E test suite is opt-in (skipped when no gateway is running) — full CI run requires Docker + a built image; smoke-only tests run in unit-test mode
- README-driven onboarding only — no separate docs/ site or contribution guide for the gateway package
- No multi-session support in gateway (single `PinnedBackend` per process) — multi-client concurrency is in v2 requirements (`GW-V2-03`, `GW-V2-04`)
- Unified disassembler abstraction was explicitly deferred (`DIS-V2-01`); current pass-through under native names is the v1 contract
