<objective>
Wire the container so a single launcher (`run_docker.sh`) selects between two opt-in modes from one image:

1. **Local mode** (default `./run_docker.sh`): byte-identical to v1 — `docker compose run --rm kali` interactive bash; no host port published; gateway daemon NOT started.
2. **Remote mode** (`./run_docker.sh --remote`): `docker compose -f compose.yaml -f compose.remote.yaml up -d kali` detached; gateway listens on `0.0.0.0:8080` in-container, published to host via `MCP_GATEWAY_HOST_BIND:MCP_GATEWAY_HOST_PORT` (default `0.0.0.0:8080`); token block printed for paste-into-`.mcp.json`.

Mode is gated by a new env var `MCP_GATEWAY_ENABLED` (default 0, mode-driven by `run_docker.sh`). Compose's `run` vs `up` semantics already guarantee `ports:` does not leak in local mode (Compose docs verified — `run` does not publish without `--service-ports`).

Output: 4 file edits (`compose.yaml`, `compose.remote.yaml` [new], `Dockerfile`, `run_docker.sh`) + 4 new smoke scripts under `.planning/phases/03-container-integration/scripts/`.

### Critical Compose semantic (verified from Docker docs)
- `docker compose run --rm <svc>` does NOT publish `ports:` unless `--service-ports` is passed.
- `docker compose up -d <svc>` publishes all `ports:`.
- This is why a single unconditional `ports:` block in `compose.yaml` is safe — local mode (`run --rm`) silently ignores it.
- Plans MUST NOT add `--service-ports` anywhere.

    ```bash
    #!/usr/bin/env bash
    # Shared bash assertion helpers for Phase 3 smoke scripts.
    # Sourced by smoke-local.sh and smoke-remote.sh.

    # red/green ANSI for human-readable output (no-op in non-tty)
    if [[ -t 1 ]]; then
      _ASS_RED=$'\033[0;31m'; _ASS_GREEN=$'\033[0;32m'; _ASS_RESET=$'\033[0m'
    else
      _ASS_RED=""; _ASS_GREEN=""; _ASS_RESET=""
    fi

    assert_contains() {
      # $1 = haystack, $2 = needle (literal substring), $3 = label
      local haystack="$1" needle="$2" label="$3"
      if [[ "$haystack" == *"$needle"* ]]; then
        printf '%s[pass]%s %s\n' "$_ASS_GREEN" "$_ASS_RESET" "$label"
      else
        printf '%s[fail]%s %s\n' "$_ASS_RED" "$_ASS_RESET" "$label"
        printf '       expected substring: %q\n' "$needle"
        printf '       in: %s\n' "$haystack"
        return 1
      fi
    }

    assert_no_match() {
      # $1 = haystack, $2 = needle (literal substring), $3 = label
      local haystack="$1" needle="$2" label="$3"
      if [[ "$haystack" != *"$needle"* ]]; then
        printf '%s[pass]%s %s\n' "$_ASS_GREEN" "$_ASS_RESET" "$label"
      else
        printf '%s[fail]%s %s\n' "$_ASS_RED" "$_ASS_RESET" "$label"
        printf '       unexpected substring present: %q\n' "$needle"
        return 1
      fi
    }

    assert_exit_0() {
      # $1 = label, then the command (as remaining args)
      local label="$1"; shift
      if "$@" >/dev/null 2>&1; then
        printf '%s[pass]%s %s\n' "$_ASS_GREEN" "$_ASS_RESET" "$label"
      else
        local rc=$?
        printf '%s[fail]%s %s (exit %d)\n' "$_ASS_RED" "$_ASS_RESET" "$label" "$rc"
        printf '       command: %s\n' "$*"
        return 1
      fi
    }

    assert_eq() {
      # $1 = actual, $2 = expected, $3 = label
      local actual="$1" expected="$2" label="$3"
      if [[ "$actual" == "$expected" ]]; then
        printf '%s[pass]%s %s\n' "$_ASS_GREEN" "$_ASS_RESET" "$label"
      else
        printf '%s[fail]%s %s\n' "$_ASS_RED" "$_ASS_RESET" "$label"
        printf '       actual:   %q\n' "$actual"
        printf '       expected: %q\n' "$expected"
        return 1
      fi
    }
    ```

|----------|-------------|
| host LAN → kali container `/mcp` | Untrusted clients on the host network may probe the published port (D-04 default 0.0.0.0). Bearer auth (Phase 2 GW-04) is the trust gate. |
| terminal scrollback / `docker compose logs` | The bearer token transits stdout (D-07 print block) and gateway log line. Anyone with terminal access or `docker logs` access sees the token. |
| host shell history → `--token=<value>` flag | If a user pins the token via `./run_docker.sh --token=secret`, the value lands in shell history. |
| `compose run` (local) ↔ `compose up -d` (remote) | Two different invocation modes share one image and one entrypoint script; a regression in the entrypoint's mode-gating could leak the gateway daemon into local mode. |
