<objective>
Close the D-15 "tools never raise" contract hole identified in 09-VERIFICATION.md
(truth #7). Two confirmed escape paths bypass the four D-15 error shapes when
the user-facing `capa` tool is called via `start_tool_job`:

  1. `kwargs={}` → `_build_capa_argv` does `kw["sample"]` → `KeyError('sample')`
  2. `kwargs={"sample": "../etc/passwd"}` → `samples.resolve_sample` raises
     `ValueError("path traversal rejected")`

Both currently propagate uncaught out of the MCP boundary because
`tools/jobs.py::start_tool_job` only catches `JobCapReached` from
`registry.submit()`. This violates the must-have "every error path returns ONE
of the four D-15 shapes; tools NEVER raise."

Purpose: Restore the D-15 contract for the only user-facing job spec shipped in
Phase 9 (`capa`), without altering the existing test scaffolding or the four
D-15 error class shapes.

Output: Two targeted code edits + two new test cases. No new modules, no
schema-validator dependencies, no behavioural changes for `_sleep_probe` /
`_log_burst_probe` / unknown-tool / unknown-id paths.

Scope explicitly EXCLUDES the CR-03 submit-lock gap and WR-03 line_buf unbounded
growth flagged in REVIEW.md — those are warnings, not D-15 escapes, and belong

class InvalidKwargs(Exception):
    def __init__(self, field: str, expected: str, got: str):
        self.field, self.expected, self.got = field, expected, got
        super().__init__(f"invalid kwargs: field={field!r} expected={expected!r} got={got!r}")

    def to_dict(self) -> dict:

            "error": "invalid kwargs",
            "field": self.field,
            "expected": self.expected,
            "got": self.got,
        }
