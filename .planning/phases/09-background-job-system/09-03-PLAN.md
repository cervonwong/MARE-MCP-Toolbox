Wire Phase 9 into the gateway's startup/shutdown lifecycle: add the `JOB_REGISTRY` module-level slot to `session_state.py`, nest a `BackgroundJobRegistry` async-context-manager inside `SessionRegistry` in BOTH `app.py::lifespan` branches per D-25, and add the single import + register call to `tools/__init__.py::register_all_tools` so the four Plan-02 tools become discoverable.

Purpose: Plan 01 built the primitive. Plan 02 built the MCP surface. Plan 03 is the surgical edit that makes both visible to MCP clients and ensures correct shutdown ordering. The D-25 nesting (PinnedBackend > SessionRegistry > BackgroundJobRegistry > mcp.session_manager) is critical: on shutdown, jobs get cancelled FIRST (their drive tasks may be driving r2 sessions); THEN r2 sessions get killed; THEN PinnedBackend tears down. Reversing this could leave Phase 11's session-orchestrated jobs holding stale r2 session handles mid-cancel.

This is intentionally a small plan — Plan 03 has ONE concrete task that touches three files. It runs in Wave 2 alongside Plan 02 (no shared files; Plan 03 only consumes Plan 01 and Plan 02's exports).

            idle_s=SESSION_IDLE_S,

    if backend_name is None:
        # ... no-backend path:
        async with _build_registry() as registry:
            session_state.SESSION_REGISTRY = registry
            try:
                async with mcp.session_manager.run():

            finally:
                session_state.SESSION_REGISTRY = None

                    async with mcp.session_manager.run():
                        yield
                finally:
